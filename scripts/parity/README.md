# Python ↔ Rust parity harness

Historical runtime differential tooling uses `spektrafilm` 0.3.4 at commit
`3bb2c2d2801ff68b92019cf1dbcbb133d60832bc` and the audited Rust baseline
`9dd59b0380194b93686aaa230a8bb9680aa270a4`. There is no 0.3.4 release tag;
the historical harness verifies the commit before measuring anything.

LUT acceptance and the package spectral fixture instead use experimental
runtime `28bf883e1672e884307edc75852549376e13644e`. The Rust LUT public
stops/native contract is retained. Acceptance independently derives automatic
stops and gain from the Python registry and transfer white, then translates
that gain to upstream `exposure_ev = log2(gain / input_midgray_gain)`.
The reference explicitly retains the Rust input knee `(0.815, 1, 1.2)` and
OkLch output knee/lightness `(0.95, 1, 1.6)` rather than upstream creator
defaults. Metadata schemas differ; shared artifacts and transforms are compared
without claiming identical exposure metadata. Hanatos input compression uses
upstream's fixed D65 center, independently of film-reference adaptation.
The reference registry explicitly retains historical HLG midgray `0.18` for
both input and output instead of experimental BT.2408 `26.238265737` nits.
Automatic stops use the scalar transfer white, matching the historical
contract. The f64 core regression retains six saturated F-Log samples from
independent 28bf `BundleBuilder`, resolution 4, NumPy 2.5.3, float32 transport
input, gain 1 and the runtime gamut defaults above. Its Portra reference white
is D55; the samples distinguish fixed D65 compression from film-centered
compression. Python's `[blue, green, red]` table axes are converted explicitly
to Rust's red-major indexing. The acceptance budget remains `2e-6`.

Experimental upstream removed input OkLch, which remains a supported Rust
override. Acceptance loads only that independent compressor from the clean
historical `3bb2c2d` checkout designated by `SPEKTRAFILM_PY_HISTORICAL_REPO`.
The spectral pipeline and XY compressor remain pinned to `28bf883`; the report
records both reference commits. Explicit override knees match the TOML inputs.

The package spectral oracle is generated by `package_reference.py` from the
pinned experimental checkout and stored in `fixtures/package_28bf883/` with
source/data hashes, generator hash, Python/dependency versions and generation
command in `provenance.json`. Regeneration does not establish acceptance.

## Headless GUI acceptance

`just gui-headless` runs the GUI App with `egui_kittest` and the real CPU
workers. It does not require a display server, OCR, or a native file chooser.
The same tests run in the workspace test step of `just ci` and `just verify`.
The tests use isolated state, image, and output files. They drive production
controls and check scanner mode changes, numeric edits, rendering, state
restoration, and image output.

Render actions wait for pending state-load previews and worker jobs to drain
before clicking the enabled production button. Parameter edits can supersede
those previews; a click while the button is disabled does not request a render.

Save and Export tests enter at the selected-path boundary. They use the same
conversion, worker, and writer as the native dialog actions. These tests do not
check file chooser interaction or prove native desktop acceptance.

`just gui-layout` renders focused layouts offscreen through WGPU. It requires
a usable adapter; a software adapter is sufficient. It checks control geometry
and captures rendered pixels. Set `SPEKTRAFILM_GUI_SNAPSHOT_DIR` to a directory
outside the repository to retain PNGs for review. This command runs separately
from the default PR gate.

Run the native GUI gate below for changes to window integration, file choosers,
GPU presentation, display scaling, platform color management, or shutdown.
Retain native desktop evidence for releases. Headless behavior and offscreen
layout results must identify their scope separately from native desktop results.

### Fresh provenance gate

Runtime evidence is accepted only for the exact Rust runtime commit
`a1910231fbd2c049c5177b539b6e7963c97f4e90`. `run_parity.py` rejects another
checkout, a dirty worktree (including untracked files), or a non-executable
CLI. Its report records the complete lowercase SHA256 of the executable.
`gen_matrix.py` re-checks that commit, requires `rust_worktree_dirty: false`,
requires a syntactically complete executable hash, and compares the hash with
the recorded binary when that path is available. It therefore rejects copied
or stale runtime reports rather than treating old rows as fresh evidence.

Keep source and evidence separate when running the clean a191 runtime
worktree. For example, with the report artifacts outside the checkout:

```bash
RUNTIME=/tmp/spektrafilm-a191-20261007
OUT=/tmp/spektrafilm-a191-parity-fresh
SPEKTRAFILM_RS_BIN=/tmp/spektrafilm-a191-target/release/spektrafilm-f64 \
  python3 "$RUNTIME/scripts/parity/run_parity.py" --out-root "$OUT"
python3 "$RUNTIME/scripts/parity/gen_matrix.py" \
  --report "$OUT/parity_report.json"
```

The runtime checkout itself must remain clean; `--out-root` is intentionally
outside it. A report from another commit, a dirty checkout, or a replaced
binary fails before matrix generation.

```bash

# existing Python fixtures must live at <out-root>/fixtures/<scenario>/
python3 scripts/parity/run_parity.py --rust-only --out-root target/parity

python3 scripts/parity/run_parity.py --record-unsupported
```

Exit codes: `0` every current row within its unchanged budget; `1` budget
failure, missing tap or invalid run; `2` unsupported prerequisites. Original
gap descriptions live under `audit_baseline` and never excuse current drift.

Per-scenario artifacts land in `target/parity/fixtures/<scenario>/`:
For manually generated references, pass `py_reference.py --out-dir
<out-root>/fixtures`; `run_parity.py --out-root <out-root> --rust-only`
expects that exact directory. A reference root named `python` needs an
explicit `fixtures` alias before running the Rust comparison.


- `input.tif` — shared float32 linear fixture (both sides read this file);
- `py_<tap>.f64` / `rs_<tap>.f64` — little-endian f64 dumps per topology
  tap (`log_e_film`, `cmy_film`, `log_e_print`, `cmy_print`, `rgb_out`);
- `rs_params.json` — the exact Rust param overrides sent to the CLI.

Python produces taps through `SimulationPipeline.process(collect=...)`
(named topology taps, `runtime/topology.py`). Rust produces them through
env-probe hooks in the core pipeline (`SPEKTRAFILM_DUMP_FILM_LOG_RAW`,
`SPEKTRAFILM_DUMP_FILM_DENSITY`, `SPEKTRAFILM_DUMP_PRINT_LOG_RAW`,
`SPEKTRAFILM_DUMP_PRINT_DENSITY`) plus `--raw-out` for the final buffer,
with `SPEKTRAFILM_BACKEND=cpu` so the dumps are produced by the same CPU
code path the arithmetic budgets describe.

## Interpretation rules

- **expected_parity** rows must meet their budget; failures block.
- Original gap observations are retained under **audit_baseline**. Current
  migrated scenarios require parity and exceeding their budget blocks.
- **historical** rows guard the preserved 4×4 bare-chain evidence
  (≈1.14e-8 measured 2026-09-30; see `docs/parity/baseline_evidence.md`).
- Canonical Python parameter names reach strict Rust validation unchanged;
  the harness neither renames grain controls nor drops debug/tap fields.
- Stochastic appearance (layered grain, glare) is judged by the
  `statistical_texture` moment budget, not per-pixel equality.

## LUT and package acceptance

Install the pinned Python LUT creator dependencies and `opencolorio` alongside
the reference runtime. The Linux CI gate runs the full runtime catalog and:

```bash
python scripts/parity/lut_acceptance.py \
    --cli target/release/spektrafilm-f64 --data-dir data \
    --evidence-dir target/lut-acceptance
```

The LUT gate compares numeric QA metrics and the original PASS/FAIL/INFO
statuses independently. An upstream quality failure remains a failure in the
delivered QA report; acceptance requires the same result as the pinned Python
implementation. Relative tolerance is `1e-5` with a `1e-7` absolute floor.
Independent format readers and OCIO processors exercise the delivered files.
The same gate compares 32 additional diagnostic results for disabled xy and
active oklch input compression, separately from the 112 baseline results.


The package smoke command always covers installed image/metadata/RAW paths,
LUT/OCIO/QA delivery and binary provenance. Native GUI acceptance is optional:
pass `--gui` only for a real desktop/Xvfb run. The release workflow currently
omits `--gui` by design, so its three package jobs do not claim GUI coverage;
the GUI driver remains available as a separate, explicit evidence command.
When enabled, the driver operates real windows and file dialogs, records
screenshots, saves/restores state across restart, decodes RAW, saves the retained
output, observes the GUI's independent Export worker, and checks cancellation
and window-close cleanup. Linux GUI runs use Xvfb with a session bus created
inside that display; Windows/macOS require a real interactive desktop and
platform permissions.

The package GUI driver locates Cancel and checks the in-flight status from the
same captured frame, then sends one click without another scroll or OCR pass.
Window close also checks the visible in-flight status without scrolling. The
driver requires cancellation completion and absent destination files after both
actions. Extra observations before dispatch can outlast a short export and click
the replacement Export button instead.

Export control OCR is bounded by the rendered dialog title bar and button row.
Equalized and autocontrasted crops provide independent observations of each row;
the driver does not combine their word widths or control coordinates. Selected
combo values are read as single-line crops on the value side of their observed
labels, before opening each menu and after selecting an option. Spaces and
punctuation do not change option identity; the observed `WGPU 32` OCR spelling
is accepted for `WGPU f32`, but CPU values cannot satisfy a GPU selection.
The pointer parks in the measured blank header gap, not over the dialog title,
so the captured cursor cannot corrupt title recognition in the next frame.
Popup OCR uses the changed rectangle next to the observed combo button, not an
expanded dialog crop that includes other controls or the preset browser. Only
complete option rows are clickable; the color-space help paragraph is not an
option. A clipped popup scrolls one wheel event at a time over an observed option,
in the direction given by the option order in `ExportDialog::show`. The driver
remeasures the popup after each scroll and the dialog after each selection.
Before submitting, it checks the requested controls and rendered transfer rule
again and locates Export file beside Cancel in that same frame. It distinguishes
the sidebar opener from the Export options heading. These screen observations
do not replace the operation report or decoded output checks.

Each GUI launch keeps its operation reports in a separate directory under
`diagnostics/`. Restart scenarios retain earlier reports; observations identify
each session directory. Report publication failures appear in the GUI status on
every tab.

Viewer comparisons exclude both the 260px preset browser and the 320px controls
sidebar in the default photo-first workspace. Exact zoom verification sizes the
window to fit the full 400% raster, then restores its dimensions.
Paper-back readiness uses the selected layer in the viewer status overlay;
OCR ordering of the layer name and zoom text does not determine readiness.
Zoom and rotation geometry use the known colored Input raster, selected after
the render completes. Processed Output can be nearly neutral; its dimensions
and metadata are checked separately through render reports and decoded Export.
White-padding verification waits for the requested white border before
measuring pixel differences; an unrelated changed frame is not completion.
Crossfade verification disables automatic preview while changing exposure,
then clicks Preview to request the animated render.
The Linux file chooser driver tracks its native window through closure and
locates the primary action beside Cancel in the window's bottom button row.
It does not treat the Open files read-only checkbox as an Open action.
Export-modal selection measures the rendered button fill and reads its interior
separately from labels and summary text. Popup OCR uses the adjacent changed
region, including color menus that expand beyond their button's width; selected
values must then be visible in the closed controls. Failed popup observations
retain before/open frames, a difference mask, and candidate bounds under the
evidence directory rather than treating source-order guesses as selected state.
Fixed-transfer EXR, JPEG, and PNG selections also read the modal's full-size
transfer explanation; small summary text alone can lose letters during OCR.
TIFF still requires its observed summary and editable transfer checkbox.
The submit row is bounded by Cancel's rendered button fill, excluding the
estimated-size paragraph above it; its label must be visible beside Cancel.
After discovering a native chooser, visibility checks query that exact X11
window rather than searching every GTK window again before each key press.
The native header is read as one continuous row as well as in panel crops;
long GPU adapter details can place an export's filename across a panel boundary.
Scanner acceptance navigates canonical search paths to the actual Scan/Scanner
owner. It exercises fixed-readout polarity, standard automatic conversion,
finished-positive operator exposure, Restore automatic and readout optics, then
round-trips state and compares decoded full-resolution Scan/Save pixels. The
retired editable scanner lamp and neutral/custom-style probe are not controls
of this acceptance flow; acquisition illumination remains a separate Convert
owner check and must leave the scanner unchanged.
Factory restore acceptance confirms the standalone Restore button and its
completion status before comparing canonical state and restarting.
Preview-cache resolution compares nonmagnifying fitted Input rasters: exact
zoom and magnification intentionally sample the full source, independent of
the preview-size bound. The comparison uses the same measured image rectangle
in both captures and retains the whole-canvas delta separately; the unchanged
pixel-change threshold is not diluted by unrelated gray background. Rotation
float inspection reads the overlay below the layer tabs, not the tabs themselves.
Profile selection distinguishes its own label from Camera's inherited-profile
prose, parks the pointer off text, and scrolls inside the observed popup.
Save/Export completion combines visible completed status, the exact destination,
decoded pixels/depth and the GUI's actual operation report; tiny filename OCR
