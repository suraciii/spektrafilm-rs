Product design / pinned Python 0.3.4

Rust GUI 产品对齐计划

目标不是复制 Napari 的实现，而是让用户在 Rust GUI 中以同样的工作流完成“加载 → 调参 → 预览/扫描 → 检查 → 保存/导出”，并保持显示状态、运行状态和输出状态不混淆。

用户任务

完成一张照片

用户应始终知道当前输入、当前模拟结果、当前查看层，以及下一步是 PREVIEW、SCAN 还是 SAVE/EXPORT。

产品原则

中央查看，右侧控制

中央 viewer 保持稳定；右侧 sidebar 负责分组控件；底部 action bar 负责会改变运行结果的动作。

边界

显示不污染输出

ICC、插值、白边、纸背和动画只作用于 viewer artifact，不得改变保存或 f64 export 的像素。

核心用户流程

01

Load / Configure

MAIN → Open、Input image、RAW、Profiles、Exposure、Crop。

02

Simulate / Compare

Preview 或 Scan；Input / Output / Paper back 切换；查看浮点像素和状态。

03

Save / Export

选择 saving color/depth 后 Save；需要参考精度时 Export 到 f64 CPU。

Pipeline stateRuntime params + selected profiles改变后按 Auto preview/debounce 触发；Preview/Scan 使用同一份有效参数。输出尺寸、状态文本和输出像素随参数变化。

Issue 切分原则

  • 本产品 issue 只拥有用户可观察的 workflow、layout、interaction 和验收标准。
  • GUI state/persistence 继续引用 #11；viewer/display/paper presentation 继续引用 #12；最终证据门禁归 #17。
  • 不引入新的 GUI toolkit；继续使用 egui/wgpu 和当前异步 worker。
  • 不把“编译通过”当作 GUI parity 证据；必须执行真实窗口和改变路径。
