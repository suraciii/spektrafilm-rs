# Procedural grain design
- The [Procedural contract](spec.md) owns its post-scan placement. Linear export decodes the selected transfer after Procedural; it does not rerun Procedural in linear RGB. A future material-domain algorithm would need its own numerical definition and acceptance; relabeling or moving the existing RGB stage is not that adaptation.
- Profile lookup resolves defaults into one immutable Procedural parameter set before dispatch. The CPU reference and GPU implementation consume the same resolved semantic inputs; backend-specific packing must not change them.
- WGPU owns texture generation, sampling, and composition in its device command sequence. Backend selection follows [GPU backend selection](../../gpu-execution/spec.md#backend-selection); a fused resident decline may use another complete GPU sequence but must not silently substitute the CPU Procedural stage. An explicit GPU request fails before publication when no complete GPU sequence is eligible, while automatic CPU selection is allowed only when no usable hardware GPU exists.
- CPU and WGPU share portable math, texture boundaries, phase/seed addressing, and operation order. Device arithmetic may differ only within [GPU numerical alignment](../../gpu-execution/design.md#numerical-alignment), and model-defined random values must satisfy [stochastic alignment](../../gpu-execution/design.md#stochastic-alignment).
- Procedural does not depend on Spektra density layers, Poisson parameters, or film-profile grain chemistry.
